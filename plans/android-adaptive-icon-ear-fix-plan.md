# Android Adaptive Icon Ear Clipping Fix Plan

## Problem

After replacing the Android app icon with the Tarsier logo (from `logo.png`), the Tarsier's ears are clipped/cut off on the Huawei phone's home screen. The `logo.png` file shows the full Tarsier with ears when opened directly, but the installed app icon has the ears missing.

## Root Cause

Android adaptive icons (API 26+, used by all modern Android devices) apply a **device-specific mask** to app icons. Each manufacturer defines their own shape:

| Manufacturer     | Mask Shape                    |
| ---------------- | ----------------------------- |
| Huawei (EMUI)    | Squircle (rounded square)     |
| Samsung (One UI) | Rounded square (more rounded) |
| Google Pixel     | Circle                        |
| Xiaomi (MIUI)    | Rounded square                |

These masks clip approximately **33% of the outer edge** of the icon image. Only the inner **~67% "safety zone"** is guaranteed visible across all devices.

The current `ic_launcher_foreground.png` files were generated by simply resizing `logo.png` (500×500) to each density target size — the Tarsier logo fills most of the image, causing the ears to extend into the clip zone.

**Visual diagram:**

```
┌──────────────────────┐
│  Outer 33% clip zone │  ← Ears are here → CLIPPED
│   ┌──────────────┐   │
│   │  Safety zone │   │  ← Inner 67% guaranteed visible
│   │  (67%)       │   │
│   │   ┌──────┐   │   │
│   │   │Tars. │   │   │
│   │   └──────┘   │   │
│   └──────────────┘   │
└──────────────────────┘
```

## Solution

Regenerate the `ic_launcher_foreground.png` files with the Tarsier logo **scaled down (~60-67%) and centered** on a transparent canvas. The white background layer (`@color/bootsplash_background` = `#ffffff`) will fill the outer area, so the clipped zone appears white while the logo (with ears intact) sits safely in the center.

### Target image specifications

For each density, the final foreground PNG should have:

- **Canvas size**: Same as density target (48×48, 72×72, etc.)
- **Logo size**: ~67% of canvas (so logo fits within safety zone)
- **Background**: Transparent (the XML background layer handles the color)
- **Position**: Centered

### Calculation table

| Density | Canvas (px) | Logo target (px) @ ~67% | Command (resize then canvas)                                       |
| ------- | ----------- | ----------------------- | ------------------------------------------------------------------ |
| mdpi    | 48×48       | 32×32                   | `-resize 32x32 -background none -gravity center -extent 48x48`     |
| hdpi    | 72×72       | 48×48                   | `-resize 48x48 -background none -gravity center -extent 72x72`     |
| xhdpi   | 96×96       | 64×64                   | `-resize 64x64 -background none -gravity center -extent 96x96`     |
| xxhdpi  | 144×144     | 96×96                   | `-resize 96x96 -background none -gravity center -extent 144x144`   |
| xxxhdpi | 192×192     | 128×128                 | `-resize 128x128 -background none -gravity center -extent 192x192` |

### One-liner script

```bash
SOURCE="logo.png"
BASE="android/app/src/main/res"

for SIZE in mdpi:48 hdpi:72 xhdpi:96 xxhdpi:144 xxxhdpi:192; do
  DIR="${BASE}/mipmap-${SIZE%%:*}"
  PX="${SIZE##*:}"
  LOGO_PX=$((PX * 67 / 100))  # ~67% of canvas

  magick "$SOURCE" -resize "${LOGO_PX}x${LOGO_PX}" \
    -background none -gravity center -extent "${PX}x${PX}" \
    "$DIR/ic_launcher_foreground.png"
done
```

This regenerates only the 5 `ic_launcher_foreground.png` files (one per density). The `ic_launcher.png` and `ic_launcher_round.png` files (full-bleed versions) remain unchanged.

## Background color consideration

Current background: `#ffffff` (white) from `colors.xml` → `bootsplash_background`.

The BootSplash folder is named `BootSplashLogo-3f4c85.imageset`, suggesting the brand color `#3F4C85`. If you prefer a brand-colored background instead of white, update `colors.xml`:

```xml
<color name="bootsplash_background">#3F4C85</color>
```

However, this also affects the splash screen (BootSplash), not just the app icon. Keeping `#ffffff` is simpler and matches iOS.

## Prerequisites

- ImageMagick (`magick` command) — already installed via Homebrew
- `logo.png` (500×500) — exists at project root

## Fallback (if adaptive icon approach doesn't work)

If adaptive icons continue to cause issues, a non-adaptive approach can be used:

- Remove/rename the `mipmap-anydpi-v26/` directory
- Set `ic_launcher.png` to a composited image (logo on colored background, full-bleed)
- This shows the full square icon without any mask (like iOS)
- But the icon would be square on all devices (no adaptive masking)
